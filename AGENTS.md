# Repository Workflow

- Make all changes on an independent feature branch. Never edit or commit directly on main, satori, or another integration branch.
- Continue all current website work on the existing `feature/ljt` branch. Do not create a new branch for each change.
- The user handles commits, pushes, and pull requests. Do not perform these actions without a new explicit request; the one-time correction of the previous commit is authorized separately.
- Submit changes through a pull request. Do not push feature commits directly to an integration branch or merge without explicit approval.
- Before integration, provide a change report in the pull request containing the scope, changed files, validation results, known limitations, and impact on existing behavior or styling.
- Preserve unrelated user changes and staged files; commit only files belonging to the task.
